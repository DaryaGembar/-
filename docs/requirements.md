# Требования к API «Пиццаед» (PizzaEat)

> Документ описывает функциональные и нефункциональные требования к учебному интернет-магазину «Пиццаед» (aiqa.su/base/shop).
> Источник: Postman-коллекция + поведение API, разведённое вручную.
> Версия документа: **v1.0** · Дата: 2026-05-30

## 0. Мета

| Поле          | Значение                                                                         |
| ------------- | -------------------------------------------------------------------------------- |
| Имя системы   | Пиццаед (PizzaEat)                                                               |
| Тип           | Учебный REST API интернет-магазина                                               |
| Базовый URL   | `https://aiqa.su`                                                                |
| API prefix    | `/api/course/v1/shop`                                                            |
| Авторизация   | Без аутентификации. Изоляция данных — через заголовок `X-Course-Session: <uuid>` |
| Формат данных | JSON, UTF-8                                                                      |
| Окружения     | Только `prod`-like (https://aiqa.su). Staging/test среды не предоставляются      |

## 1. Глоссарий

| Термин         | Определение                                                                            |
| -------------- | -------------------------------------------------------------------------------------- |
| Товар          | Единица каталога: пицца, напиток, десерт, соус. Имеет цену, наличие, рейтинг, бейджи   |
| Корзина (Cart) | Состояние «ещё не оформленного» заказа в рамках сессии. Привязана к `X-Course-Session` |
| Заказ (Order)  | Подтверждённый набор товаров с рассчитанными суммами, сохранённый в истории            |
| Сессия         | Произвольный UUID в заголовке `X-Course-Session`. Служит ключом изоляции данных        |
| Промокод       | Строковое значение, дающее скидку. В текущей версии поддерживается только `QA60`       |
| Чизкейк        | Конкретный товар-пример, у которого `in_stock = false` всегда                          |
| Out-of-stock   | Состояние товара, при котором его нельзя положить в корзину                            |

## 2. Роли и сценарии

| Роль               | Что делает                                                   |
| ------------------ | ------------------------------------------------------------ |
| Гость / покупатель | Смотрит каталог, кладёт товары в корзину, оформляет заказ    |
| Бэкенд-сервис      | Считает суммы корзины, применяет промокоды, фиксирует заказы |

UI/фронтенд в задачу **не** входит — тестируется только REST API.

## 3. Функциональные требования

> Идентификатор `R` + число. Каждое требование описывает **одно наблюдаемое поведение** и привязано к эндпоинту.

### 3.1 Каталог

- **R1. Полный список товаров.** `GET /products` без параметров возвращает **200** и массив всех товаров. Поля каждого товара: `id`, `name`, `category`, `description`, `price`, `rating`, `badges[]`, `in_stock`.
- **R2. Поиск по строке.** `GET /products?q=<строка>` возвращает только товары, у которых подстрока (case-insensitive) встречается в `name`, `description` или хотя бы в одном `badges`. Поиск **не** ограничен категорией.
- **R3. Фильтр по категории.** `GET /products?category=<значение>` возвращает только товары с этим `category`. Допустимые значения: `pizza`, `drink`, `dessert`, `sauce`. Товары с другими категориями не возвращаются.
- **R4. Фильтр по наличию.** `GET /products?in_stock=true` — только товары с `in_stock = true`. `?in_stock=false` — только `false`. Без параметра — все.
- **R5. Получение одного товара.** `GET /products/{id}` для существующего `id` возвращает **200** и объект товара. Для несуществующего `id` — **404**.
- **R6. Состав полей товара.** У каждого товара обязательно присутствуют `id`, `name`, `price` (число, ≥ 0), `in_stock` (boolean). Остальные поля могут быть пустыми массивами/нулевыми значениями, но не отсутствовать.

### 3.2 Корзина

- **R7. Получение текущей корзины.** `GET /cart` возвращает **200** и объект `{ items: [...], subtotal, discount, delivery, total }`. Если корзина пуста — `items = []`, числовые поля = `0`.
- **R8. Добавление товара.** `POST /cart` с телом `{ product_id, quantity }` для товара `in_stock = true` возвращает **201** и обновлённую корзину. Товар появляется в `items` с указанным `quantity`.
- **R9. Запрет добавления отсутствующего товара.** `POST /cart` с `product_id`, у которого `in_stock = false` (например, «cheesecake»), возвращает **422** и сообщение об ошибке со словом `stock`.
- **R10. Изменение количества.** `PATCH /cart/{productId}` с телом `{ quantity }` возвращает **200** и обновлённую корзину. Допустимый диапазон `quantity`: **1–20**. Товар в корзине должен существовать.
- **R11. Удаление через quantity = 0.** `PATCH /cart/{productId}` с `quantity: 0` возвращает **200**, товар исчезает из `items`. Альтернативный сценарий — `DELETE /cart/{productId}` (см. R12).
- **R12. Удаление через DELETE.** `DELETE /cart/{productId}` возвращает **200** и корзину без удалённого товара.
- **R13. Пересчёт сумм.** После **каждой** мутации (POST/PATCH/DELETE) `subtotal`, `discount`, `delivery`, `total` пересчитываются и совпадают с ручным расчётом по бизнес-правилам (раздел 4).
- **R14. Повторное добавление.** Если товар уже в корзире, повторный `POST /cart` с тем же `product_id` **увеличивает** `quantity` (либо возвращает ошибку — уточнить, см. Open Questions §10, OQ-1).

### 3.3 Заказ

- **R15. Создание заказа.** `POST /orders` с телом, описывающим корзину и промокод, возвращает **201** и объект заказа со статусом `created`. Заказ содержит все позиции, применённую скидку и расчёт доставки.
- **R16. Состав полей заказа.** В ответе присутствуют как минимум: `id`, `items[]`, `subtotal`, `discount`, `delivery`, `total`, `status`, `promo_code` (если был применён).
- **R17. Пустая корзина.** `POST /orders` с пустой корзиной возвращает ошибку (статус уточнить, см. OQ-2).

## 4. Бизнес-правила

> Идентификатор `BR`. Правила — **наблюдаемые**, проверяются по ответам API. Если правило нарушается — это баг.

### 4.1 Скидки и промокоды

- **BR1. Промокод QA60.** Применяется к сумме `subtotal` (товары) **до** расчёта доставки. Размер скидки — **10%** от `subtotal`. Скидка **округляется вниз** до целых рублей (`Math.floor`).
- **BR2. Case-insensitive и trim.** Промокод `qa60`, `QA60`, `qa60`, `Qa60` — эквивалентны. Пробелы по краям игнорируются.
- **BR3. Неизвестный промокод.** Любой промокод, отличный от `QA60` (после trim и case-fold), **не применяется** и приводит к ошибке (статус уточнить, см. OQ-3) — **не** молча игнорируется.

### 4.2 Доставка

- **BR4. Стоимость доставки зависит от суммы товаров.**
  - `items_sum < 1500₽` → `delivery = 199₽`
  - `items_sum ≥ 1500₽` → `delivery = 0₽` (бесплатно)
- **BR5. Доставка рассчитывается от `subtotal` ПОСЛЕ скидки.** То есть: `delivery_basis = subtotal − discount`. Если `delivery_basis < 1500` — 199₽, иначе 0.
- **BR6. Доставка не суммируется со скидкой.** `total = subtotal − discount + delivery`. Скидка не уменьшает стоимость доставки.

### 4.3 Корзина и количество

- **BR7. Диапазон количества.** Значение `quantity` в `POST /cart` и `PATCH /cart/{productId}` — целое число **от 1 до 20** включительно. `0` — служебное значение, означающее «удалить».
- **BR8. Граничные значения.** `quantity = 1` → товар остаётся в одной позиции. `quantity = 20` — максимум. `quantity = 21` и выше — ошибка валидации (статус уточнить, см. OQ-4). Отрицательные значения — ошибка валидации.
- **BR9. Стоимость позиции.** `items_sum = Σ price × quantity` по всем позициям корзины.

## 5. Справочник API

> Компактная выжимка. Полные примеры — в `postman/PizzaEat.postman_collection.json`.

### 5.1 Заголовки

| Заголовок          | Обязательность                   | Описание                                 |
| ------------------ | -------------------------------- | ---------------------------------------- |
| `X-Course-Session` | **Обязателен** для всех запросов | UUID сессии для изоляции корзины/заказов |
| `Content-Type`     | Обязателен для POST/PATCH        | `application/json`                       |

### 5.2 Эндпоинты

| #   | Метод    | Путь                                                  | Назначение                                             | Успех     |
| --- | -------- | ----------------------------------------------------- | ------------------------------------------------------ | --------- |
| 1   | `GET`    | `/products`                                           | Список товаров с фильтрами `q`, `category`, `in_stock` | 200       |
| 2   | `GET`    | `/products/{id}`                                      | Один товар                                             | 200 / 404 |
| 3   | `GET`    | `/cart`                                               | Текущая корзина                                        | 200       |
| 4   | `POST`   | `/cart`                                               | Добавить товар `{ product_id, quantity }`              | 201       |
| 5   | `PATCH`  | `/cart/{productId}`                                   | Изменить `quantity` (0 = удалить)                      | 200       |
| 6   | `DELETE` | `/cart/{productId}`                                   | Удалить позицию                                        | 200       |
| 7   | `POST`   | `/orders`                                             | Оформить заказ                                         | 201       |
| 8   | —        | (прочие POST/GET формы оплаты, доставки, регистрации) | В текущей версии **не тестируются**                    | —         |

### 5.3 Коды ответов

| Код | Когда                                                                     |
| --- | ------------------------------------------------------------------------- |
| 200 | Успешный GET / PATCH / DELETE                                             |
| 201 | Успешный POST (создание ресурса)                                          |
| 404 | Запрошенный ресурс не найден (`/products/{id}`)                           |
| 422 | Бизнес-валидация (out-of-stock, невалидный промокод — уточнить, см. OQ-3) |

```json

  "id": "string",

  "category": "pizza | drink | dessert | sauce",
  "description": "string",
  "price": 0,
  "rating": 0.0,
  "badges": ["string"],
```

```json

  "items": [{ "product_id": "string", "quantity": 1 }],
  "subtotal": 0,
  "discount": 0,
  "delivery": 0,
  "total": 0
}
```

```json
  "total": 0,
  "status": "created",
  "promo_code": "QA60 | null"
}
```

## 7. Сквозные требования (Cross-cutting)

| ID   | Требование                                                                                    |
| ---- | --------------------------------------------------------------------------------------------- |
| NFR1 | Все ответы — валидный JSON. Сервер не возвращает HTML или текст в случае ошибки.              |
| NFR2 | Числовые поля — целые или дробные, без валютного знака. Валюта подразумевается — ₽.           |
| NFR3 | Все цены — в рублях, целая часть. Копейки не используются.                                    |
| NFR4 | Повторные запросы с тем же `X-Course-Session` идемпотентны только для GET. Для POST — нет.    |
| NFR5 | При невалидном `X-Course-Session` (пустом или отсутствующем) — поведение уточнить (см. OQ-5). |

## 8. Критерии приёмки (Definition of Done)

API считается готовым к релизу, когда выполнены **все** пункты:

1. ✅ Все эндпоинты из §5.2 возвращают корректные коды ответов согласно R1–R17.
2. ✅ Бизнес-правила BR1–BR9 выполняются на всех наблюдаемых кейсах.
3. ✅ Все обязательные заголовки (`X-Course-Session`, `Content-Type`) задокументированы и валидируются.
4. ✅ Каталог содержит минимум один товар каждой категории (pizza/drink/dessert/sauce) и минимум один товар с `in_stock = false`.
5. ✅ Корзина и заказ пересчитывают суммы по формуле `total = subtotal − discount + delivery`.
6. ✅ Промокод `QA60` работает с учётом case-insensitive и trim (BR2).
